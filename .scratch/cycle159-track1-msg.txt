Implementation:
- New crate `tools/rust/crates/v2-state-audit/` (~720 prod LOC + ~330 test LOC ≈ 1050 LOC total)
- Embedded thresholds match policy v1 (cycle 158) §4 axis values per-axis (9 axes total: channels-history, super-step-history, 4 role-histories, reconciler-poll-history, cycle-runner-cycle-history, state-json-dispatches) + cross-axis ceiling (500MB / 2GB / 4GB)
- 3 measurement primitives: file-size, directory-size (recursive), json-array-count — all tolerate missing paths (SCAFFOLD-correct: state/ does not yet exist)
- Classification: at-or-above advisory but below mandatory = Advisory; at-or-above mandatory but below hard = Mandatory; at-or-above hard = Hard
- Overall = max severity across all axes and cross-axis
- Exit codes 0/1/2/3 map to Ok/Advisory/Mandatory/Hard (no-JSON-parse consumers can read severity from exit code)
- CLI: `--repo-root <path>` (default `.`), `--json` flag (default human-readable)
- POLICY_VERSION=1 baked into report; stale-tool detection explicit

Cycle 159 finding (tool-extraction-surfaces-prior-cycle-error):

Live smoke against this repo exposed a cycle 158 policy authoring gap. Policy §4 Axis 6 names "docs/state.json dispatches array" but the actual storage key in legacy v1 state.json is `agent_sessions` (used by v2-state-dispatch-sync). Cycle 158 authored the policy without verifying against the implementation. Cycle 159 tool implementation targeted the actual key (`agent_sessions`) and surfaced 930 entries — nearly 2x the policy's hard threshold of 500. Policy doc patched in §4 Axis 6 with "Storage-key clarification (cycle 159)" recording (a) the actual storage key, (b) the live-measurement finding, (c) forward options (refuse-to-write enforcement vs threshold recalibration against 3-month growth data).

The audit tool currently exits with code 3 (hard) against this repo. This is not an active halt — hard-threshold "refuse-to-write" semantics are owner-enforced (v2-state-dispatch-sync would refuse the append); the audit tool only reports. v2-state-dispatch-sync does not yet implement refuse-to-write, so the 930-entry state is observable-but-tolerated until either enforcement is added or thresholds are recalibrated.
