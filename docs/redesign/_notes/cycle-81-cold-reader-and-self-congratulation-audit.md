findings) + the stress-test findings (1 activity producing 1 finding).

labelling-of-the-cycle's-own-shape, which is a description of process
not a deliverable improvement.

**Honest re-framing:** "Cycle N produces 2 substantive contributions
(cold-reader + stress-test) plus 1 meta-observation about the cycle's
composite shape." Removing the inflation reduces three "contributions"
to "2 contributions + 1 meta-observation," which is more accurate.

### Audit target 4: HARDENED/TESTED/NOVEL distinction utility

**Verdict: METHODOLOGICALLY USEFUL for the redesign process; NOT
operationally load-bearing for v2 cycle prescription.**

The HARDENED/TESTED/NOVEL distinction was introduced cycle 78 to
grade composite-shape evidence:
- HARDENED: ≥3 instances of the composite
- TESTED: 2 instances
- NOVEL: 1 instance

Methodological utility: the distinction grades how confident the
redesign-process should be that a composite shape is a stable
pattern vs an idiosyncratic occurrence. A HARDENED shape has
empirical basis across 3 cycles; a NOVEL shape might just be a
one-off coincidence. This is useful for the redesign process when
deciding which shapes to invest in further.

Operational utility for v2: the distinction grades shape EVIDENCE,
not shape UTILITY. Once v2 cycle prescription describes a shape,
the orchestrator either runs it or doesn't — instance count doesn't
matter operationally. v2 doesn't need to know "this shape was
HARDENED at the time of v2 design"; v2 needs to know "when this
shape applies, run it."

**Inflation observation:** framing the HARDENED/TESTED/NOVEL
distinction as v2 design-input overstates utility. It's an internal
methodology label for redesign-process confidence, not a
prescription parameter for v2 cycle behavior.

**Honest re-framing:** "HARDENED/TESTED/NOVEL distinction is
internal methodology for grading shape evidence during redesign;
v2 cycle prescription enumerates shapes without instance-grading."

**Load-bearing test:** would removing HARDENED/TESTED/NOVEL from
v2 design-input materially worsen v2? **No.** v2 cycle prescription
operates on shapes, not on shape-evidence-counts. Removing the
distinction from v2 design-input is honest qualification.

**v2 design-input from F4 (methodology-vs-prescription conflation):**
cycle hand-off discipline should distinguish REDESIGN-PROCESS
METHODOLOGY (internal practices for grading evidence) from V2
CYCLE PRESCRIPTION (operational instructions for v2 orchestrator).
Methodology informs prescription but isn't itself prescription.

## Audit synthesis: which framings are flattering vs load-bearing

**Five findings from audit:**

| Audit target | Verdict | Inflation type | v2 impact |
|---|---|---|---|
| F1: "three substantive contributions" | INFLATED | claim-counting | hand-off discipline: distinguish substantive vs process |
| F2: "five ways improved" | INFLATED | findings-vs-ways conflation | hand-off discipline: 1 activity = 1 way |
| F3: "13 distinct shapes" | AMBIGUOUS / inflated under one convention | shape-instance vs functional-class | shape catalogue should consolidate to functional-class |
| F4: HARDENED/TESTED/NOVEL distinction | METHODOLOGICALLY USEFUL but not v2 prescription material | methodology vs prescription | v2 design-input should distinguish methodology from prescription |
| F5: language-precision-lexicon load-bearing-ness | GENUINE LEARNING but catalog not prescription | catalog vs discipline | v2 prescription needs discipline not catalog |

**Common pattern across F1-F5:** the framings inflate UTILITY by
conflating different categories that are related but distinct:
- F1: substantive vs process
- F2: findings vs ways (sub-product vs improvement axis)
- F3: instance vs functional-class (specific occurrence vs type)
- F4: methodology vs prescription (internal practice vs operational instruction)
